# 暗黑类 ARPG · Cocos Creator 开发计划（MVP 优先）

> **定位**：用 Cocos Creator 3.x 从零重做一款 2D 俯视角 ARPG，目标平台为微信小游戏（后续可扩抖音等）。  
> **策略**：先跑通最小可玩闭环（MVP），再按版本迭代打磨；不赶上线。  
> **参考**：本仓库 Python + Phaser 原型（`web/static/game/`）仅作玩法与数值参考，不直接迁移代码。  
> **配置基准**：`docs/配置.json` 为长期数值目标；MVP 阶段只实现其子集，避免一次到位。

---

## 0. 原计划的修正说明

| 原 plan 条目 | 问题 | 修订 |
|-------------|------|------|
| 12 周全管线 + 提审发版 | 范围过大，单人/小团队易延期 | 拆为 **MVP（Phase 0–4）** 与 **打磨/商业化（Phase 5+）**，不设硬性周数 |
| 双精度浮点数模块 | 对小游戏 ARPG 过度设计 | 用 `number` + **大数格式化工具**（万/亿显示）即可 |
| 1000+ 同屏压测 | 微信低端机不现实 | MVP 目标 **同屏 20–40 怪 @ 30fps**；割草感靠刷怪频率而非绝对数量 |
| 行为树 AI | Mob/Elite 用状态机足够 | **有限状态机（FSM）**；仅 Boss 用多阶段状态机 |
| 12 部位 + 洗练 + 传奇特效劫持 | MVP 过重 | MVP **6 部位 + 4 品质**；12 部位与洗练进 v0.2+ |
| 第 6–8 周 IAP/战令/月卡 | 无玩家基础时过早 | 商业化整包延后到 **v0.3+**，MVP 不接支付 |
| 微信 + 抖音 + 开放数据域 + 录屏 | 多平台并行分散精力 | MVP 只做 **微信预览**；其他平台 Phase 5+ |
| 云存档 + 防作弊 | 本地单机阶段不需要 | MVP 用 **localStorage / 微信本地存储**；云同步 v0.2+ |

## 1. 版本路线图

```
v0.1 MVP     能玩一整局：选角 → 一层战斗 → 拿奖励 → 换装 → 再挑战
v0.2 养成扩展  6→8 部位、精英词条、乘区伤害、本地存档完善、云存档可选
v0.3 内容扩展  多职业、Boss 阶段、爬塔深度、Spine 正式美术
v0.4 商业化    激励视频、内购（需资质）、排行榜
v1.0 上架候选  性能压测、新手引导、提审材料、分包优化
```

**MVP（v0.1）必须包含**

- 1 个可玩职业（建议野蛮人）
- 1 张测试地图 + 虚拟摇杆移动
- 2 种小怪（近战/远程）+ 1 种 Boss
- 普攻 + 2 个主动技能
- 6 部位装备、4 品质、基础词缀
- 单层爬塔（可重复挑战，层数递增难度）
- 城镇 UI：背包 / 装备 / 简单属性面板
- 战斗结算：经验、金币、掉落入背包

**MVP 明确不做**

- 12 部位、神器品质、洗练/重铸
- 乘区 E 独立传奇乘区、技能形态劫持
- 离线挂机、战令、月卡、广告
- 云存档、防作弊、社交排行榜
- Spine 全套、完整音效、纸娃娃

## 2. 技术选型

| 项 | 选择 | 说明 |
|----|------|------|
| 引擎 | Cocos Creator **3.8+** | 2D 项目，TypeScript |
| 动画 | MVP：**序列帧**；v0.3+：Spine | 仓库 `art_asset_processing/output/` 可复用帧表 |
| 地图 | Tiled → Cocos TileMap | 或程序化房间（与 Phaser 版 `riftMap` 思路类似） |
| 配置 | JSON 表 + `ConfigLoader` | 从 `docs/配置.json` 演进，MVP 单独维护 `configs/mvp/` |
| 存档 | MVP：`sys.localStorage` | 结构参考 `saves/*.json` 字段命名 |
| 后端 | MVP：**无服务端** | 全部本地演算；v0.2+ 可选微信云开发或保留 FastAPI |
| AI | FSM（idle / patrol / chase / attack / dead） | Boss 加 `phase` 字段驱动 |


## 3. 数据与数值策略

### 3.1 配置分层

1. **`configs/mvp/`**（Phase 0 起）：角色基础、2 怪 1 Boss、6 槽位、4 品质、10 条核心词缀。  
2. **`configs/full/`**（v0.2 起）：逐步对齐 `docs/配置.json`（12 槽位、5 品质、乘区、精英词条）。  
3. **单一真相源原则**：同一字段名在 MVP 与 full 之间保持一致，只扩表不 rename。

### 3.2 MVP 伤害公式（简化）

MVP 不实现五乘区，采用可调试的简化式，与参考原型量级接近：

```
raw = base_attack × skill_multiplier × (1 + skill_damage_bonus)
if crit: raw × (1 + crit_damage)
mitigated = raw × (1 - armor / (armor + K))    // K = combat_mechanics.armor_reduction_constant
final = floor(mitigated × random(0.92, 1.08))
```

**v0.2** 再接入 `damage_zones` 的 A–E 乘区；**v0.3** 再接入 `zone_E_independent` 连乘。

### 3.3 MVP 装备槽位（6 位，映射 full 表）

| MVP 槽位 | 对应 full 配置 | 主属性 |
|---------|---------------|--------|
| weapon | main_hand | 攻击 |
| helm | helmet | 生命 |
| chest | chest | 护甲 |
| gloves | gloves | 攻击 |
| boots | boots | 移速/生命 |
| ring | ring_1 | 暴击 |

### 3.4 层数 scaling（MVP）

沿用 `配置.json` 思路，MVP 只用两项：

```json
{
  "hp_scale_per_floor": 1.15,
  "damage_reduction_per_floor": 0.02
}
```

Boss 层：每 **10 层** 大 Boss；精英：约 **15%** 刷怪概率。小 Boss（每 5 层）延到 v0.2。

## 4. 分步执行计划

每个 Step 含：**目标 → 任务清单 → 验收标准 → 产出物**。  
按顺序执行；验收通过再进入下一步。

---

### Step 0 — 工程初始化（约 3–5 天）

**目标**：Cocos 工程能跑，微信开发者工具能预览。

**任务**

- [ ] 创建 Cocos Creator 3.8+ 空 2D 项目 `cocos-arpg`
- [ ] 启用 TypeScript；配置 ESLint（可选）
- [ ] 构建发布 → 微信小游戏，真机预览通过
- [ ] 搭建 `Boot.scene`：加载进度条 + 跳转 Title
- [ ] 编写 `ConfigLoader`：异步加载 `configs/mvp/game.json`
- [ ] 编写 `EventBus`（全局事件，解耦 UI 与战斗）

**验收**

- 微信开发者工具中 Boot → Title 无报错
- 修改 JSON 中 `game_version` 后，Title 界面能显示版本号

**产出物**

- 空场景链路 Boot → Title
- `ConfigLoader.ts`、`EventBus.ts`
- `configs/mvp/game.json`（最小字段：`game_version`, `character_design.base_stats`）

---

### Step 1 — 角色移动与输入（约 3–5 天）

**目标**：玩家在地图内流畅移动，碰撞正确。

**任务**

- [ ] 导入占位 tileset（或纯色 Block）+ 一张 20×20 测试图
- [ ] 实现 `VirtualJoystick` 组件（触摸区域在屏幕左下）
- [ ] 实现 `PlayerController`：八向/四向移动，读取 `move_speed`
- [ ] 墙体碰撞（TileMap 碰撞层 或静态刚体）
- [ ] 摄像机跟随 + 边界限制

**验收**

- 摇杆移动顺滑，撞墙停止，帧率稳定
- 移速改 JSON 后体感明显变化

**产出物**

- `Dungeon.scene`（仅地图 + 玩家）
- `PlayerController.ts`、`VirtualJoystick.ts`

**参考**：Phaser 版 `DungeonScene.js` 移动与 `constants.js` 移速逻辑。

---

### Step 2 — 战斗核心：普攻与受击（约 5–7 天）

**目标**：能打怪、怪能打人、有死亡判定。

**任务**

- [ ] 实现 `StatBlock` + `PlayerStats` / `MonsterStats`
- [ ] 实现 `DamageCalculator`（MVP 简化公式）
- [ ] 玩家：自动索敌普攻（进入范围攻击最近敌人，内置 CD ~450ms）
- [ ] 怪物：FSM — `chase` → `attack`（近战距离判定）
- [ ] 血条组件（玩家 HUD + 怪物头顶）
- [ ] 实现 `ObjectPool`：飘字、怪物节点
- [ ] 死亡：怪消失 + 玩家死亡弹窗（返回城镇）

**验收**

- 1 玩家 vs 3 只近战史莱姆，能清场或死亡
- 暴击时飘字变色（可选）
- 同屏 10 怪无明显卡顿

**产出物**

- `Mob.ts`、`MobFSM.ts`、`DamageCalculator.ts`、`HealthBar.ts`
- 序列帧占位：idle / walk / attack（可从 `art_asset_processing/output/` 导入）

---

### Step 3 — 技能与资源条（约 5–7 天）

**目标**：2 个主动技能可释放，有 CD 和资源消耗。

**任务**

- [ ] 扩展 `configs/mvp/skills.json`：普攻 + 2 主动（如旋风斩、战吼）
- [ ] `SkillBar` UI：2 个技能按钮 + CD 遮罩
- [ ] `SkillExecutor`：范围伤害 / Buff（战吼增伤）
- [ ] 资源条（怒气/法力）：普攻回复、技能消耗
- [ ] 简单 VFX 占位（Graphics 或单帧特效）

**验收**

- 技能可释放、进 CD、资源不足时禁用
- 战吼 Buff 期间伤害明显提升

**参考**：`config/skills.py` 中 `whirlwind`、`war_cry` 数值。

---

### Step 4 — 刷怪与单层关卡（约 5–7 天）

**目标**：一层完整战斗流程：进层 → 清怪 → Boss → 结算。

**任务**

- [ ] `FloorController`：读取层数，计算 HP/免伤 scaling
- [ ] `MonsterSpawner`：分 2–3 波刷近战/远程混合
- [ ] 精英怪（v0.1 可选）：仅 HP×5 + 颜色描边，**暂不实现词条**
- [ ] Boss：固定刷新点，HP×50，1 阶段 2 种攻击模式（冲锋 + 扇形 AOE）
- [ ] 清场检测 → 弹出结算面板

**验收**

- 从第 1 层打到第 3 层，难度递增可感知
- Boss 战约 30–60 秒，不会卡死或穿墙

**产出物**

- `FloorController.ts`、`MonsterSpawner.ts`、`Boss.ts`
- `configs/mvp/monsters.json`、`floors.json`

---

### Step 5 — 掉落与背包（约 5–7 天）

**目标**：战斗结束有奖励，装备能进背包。

**任务**

- [ ] `LootGenerator`：按层数权重生成 0–2 件装备（4 品质）
- [ ] 结算面板：经验、金币、装备列表
- [ ] `Inventory` 数据结构（最大 40 格）
- [ ] `SaveManager`：序列化到 `localStorage`（角色名、层数、背包、已装备）
- [ ] 城镇 `BagPanel`：列表、装备/卸下

**验收**

- 打完一层 → 回城 → 背包可见新装备 → 重开游戏数据仍在
- 装备词缀显示与 `StatBlock` 聚合一致

**配置**

- `configs/mvp/equipment_slots.json`（6 槽）
- `configs/mvp/quality_multipliers.json`（4 品质，无 artifact）
- `configs/mvp/affix_pool.json`（10 条核心词缀）

**参考**：`models/equipment.py`、`config/constants.py`。

---

### Step 6 — 城镇闭环（约 5–7 天）

**目标**：完整游戏循环跑通。

**任务**

- [ ] `Title.scene`：新建/读取角色（本地存档列表）
- [ ] `Town.scene`：属性面板、背包、选层入口
- [ ] 装备对比：装 vs 卸属性变化（↑↓ 箭头）
- [ ] 升级：经验满则升级，成长读 `growth_per_level`
- [ ] 回城满血满资源
- [ ] 选层 UI：当前最高层 / 重复刷已通关层（收益 50%，可选 v0.1.1）

**验收**

```
Title 选角 → Town 查看属性 → 选第 N 层 → Dungeon 战斗
→ 结算 → Town 换装 → 再进 N+1 层
```

全流程 ≥30 分钟无阻塞 Bug。

**产出物**

- `Title.scene`、`Town.scene`
- `SaveManager.ts` 完整版
- `EquipPanel.ts`、`StatPanel.ts`

---

### Step 7 — MVP 打磨（约 7–10 天）

**目标**：v0.1 可对外演示，体验完整但美术占位可接受。

**任务**

- [ ] 替换 1 套正式序列帧（野蛮人 + 史莱姆 + Boss）

- [ ] 音效占位：攻击、受击、UI 点击（3–5 个）
- [ ] 暂停菜单：继续 / 回城
- [ ] 简单新手提示（3 步：移动 → 攻击 → 技能）
- [ ] Bug 修复与数值粗调（前 10 层可通关）

**验收**

- 非开发者试玩 10 分钟能独立完成一局循环
- 微信真机（中端 Android）Dungeon 场景 ≥30fps

**里程碑**：**v0.1 MVP 完成** 🎯

## 6. 关键系统设计备忘

### 6.1 怪物 AI（FSM，非行为树）

```
        ┌──────┐
   ┌───►│ idle │◄───┐
   │    └──┬───┘    │
   │       │ 发现玩家 │
   │       ▼        │
   │    ┌──────┐    │ 脱离范围
   │    │chase │────┘
   │    └──┬───┘
   │       │ 进入攻击距离
   │       ▼
   │    ┌──────┐
   └───►│attack│
        └──────┘
```

远程怪在 `chase` 态加 `keep_distance`：距离 < 安全距后退。

### 6.2 传奇特效扩展点（v0.2 预留接口）

```typescript
interface LegendaryEffect {
  id: string;
  onEquip(owner: Entity): void;
  onUnequip(owner: Entity): void;
  modifySkill?(ctx: SkillContext): SkillContext;
  onHit?(ctx: HitContext): void;
}
```

MVP 不实现具体传奇，但 `Equipment` 数据结构预留 `legendary_id?: string`。

### 6.3 存档结构（与参考项目对齐）

```json
{
  "name": "角色名",
  "class_id": "barbarian",
  "level": 1,
  "exp": 0,
  "gold": 0,
  "max_floor": 1,
  "hp": 100,
  "resource": 0,
  "equipment": { "weapon": null, "helm": null, "...": null },
  "inventory": [],
  "skills": [{ "id": "whirlwind", "rank": 1 }],
  "forge_levels": {}
}
```

### 6.4 从参考项目提取的内容

| 参考路径 | 用途 |

| `config/skills.py` | 技能名、CD、倍率、职业树 |
| `config/constants.py` | 词缀范围、层数曲线、掉落权重 |
| `models/equipment.py` | 装备生成算法 |
| `models/character.py` | 属性聚合顺序 |
