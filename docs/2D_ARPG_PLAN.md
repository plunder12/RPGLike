# 文字暗黑 → 2D 俯视角 ARPG 改造计划书

> 目标：把现有「回合制 / 全自动 / 文字战斗」的爬塔 RPG，改造成
> **Phaser 3 + 完全实时战斗** 的 2D 俯视角动作 RPG（类暗黑破坏神：移动、点击攻击、敌人 AI、掉落拾取）。

技术选型（已确定）：

- 前端引擎：**Phaser 3**
- 战斗方式：**完全实时**（移动 + 攻击 + 敌人追击，无回合）
- 后端：保留 **FastAPI / Python**，作为「权威数据层」（存档、装备生成、掉落、锻造）

---

## 1. 现状与目标的差距

| 维度 | 现状（v0.3） | 目标（2D ARPG） |
|------|-------------|----------------|
| 战斗循环 | `systems/battle.py` 的 `while` 回合循环，一次性算完 | 浏览器 60FPS 实时帧循环 |
| 空间 | 无坐标，单怪 1v1 | 2D 地图、坐标、多怪同屏 |
| 操作 | 无（点「挑战」自动打完） | WASD/鼠标移动、点击/按键攻击与释放技能 |
| 敌人 | 一次生成一只，无行为 | 多只、有 AI（巡逻 / 追击 / 攻击）|
| 表现 | 文字 timeline 弹层回放 | 精灵动画 + 特效 + 血条 + 受击反馈 |
| 数据流 | 请求→Python 算完→返回结果 | 进场拉数据 / 战中本地算 / 结算回传 |

**核心结论**：战斗的「进行方式」和「表现层」需要重写，但 **RPG 的数值与养成内容可几乎全部复用**。

---

## 2. 可复用 vs 需重写

### 直接复用（Python 侧，基本不动）

- `config/`：职业、技能、词缀、锻造、层数曲线等全部数值配置
- `models/stats.py`、`models/character.py`：属性聚合与角色养成
- `models/equipment.py`：装备 / 词缀生成
- `systems/save_manager.py`、`saves/`：存档
- `systems/forge.py`、`systems/equipment_shop.py`：锻造 / 售卖 / 分解
- 现有 REST API（角色 CRUD、装备、技能、锻造）大部分保留

### 需要重写 / 新增

- ❌ `systems/battle.py` 的回合循环 → ✅ 前端实时战斗（Phaser Scene）
- ❌ `systems/battle_io.py` 的 timeline → ✅ 不再需要（实时本地渲染）
- ➕ 新增「战斗结算 API」：前端把战果（击杀数、是否通关、是否阵亡）回传，Python 复用现有的经验/金币/掉落/锻造材料逻辑做结算与存档
- ➕ 前端整套 Phaser 工程：地图、角色、怪物、输入、UI

### 关键设计：把"伤害公式"抽成共享规格

当前伤害计算写在 `battle.py` 内（`_calc_damage` 等）。实时战斗在前端算，为避免「前后端两套公式」分歧，建议二选一：

- **方案 A（推荐起步）**：前端用一套简化的实时伤害公式自行计算；Python 只负责「进场给属性 + 结算给奖励」，不校验每次伤害。开发快，适合单机 / 学习项目。
- **方案 B（防作弊）**：把 attack/defense/暴击等公式固化为一份 JSON 规格，由 `/api/combat-spec` 下发，前端按规格算。后续要做联网排行榜时再升级到此方案。

> 本计划默认 **方案 A**。

## 3. 目标架构

```
┌────────────────────────────────────────────┐
│  浏览器 (Phaser 3)                            │
│  ├─ BootScene      资源加载                   │
│  ├─ TitleScene     选/建角色（调现有 API）     │
│  ├─ TownScene      城镇：背包/装备/技能/锻造 UI │
│  └─ DungeonScene   实时战斗主场景 ★            │
│       ├─ Player    移动/攻击/技能/HP           │
│       ├─ Enemy[]    AI 追击/攻击/死亡           │
│       ├─ TileMap    俯视地图 + 碰撞            │
│       └─ HUD        血条/资源/技能 CD/小地图    │
└───────────────┬────────────────────────────┘
                │ HTTP（仅进场 & 结算时）
                ▼
┌────────────────────────────────────────────┐
│  FastAPI (Python) — 权威数据层                │
│  ├─ GET  /characters/{name}      进场拉属性    │
│  ├─ POST /characters/{name}/floor/start 取本层怪物配置 │
│  ├─ POST /characters/{name}/floor/clear 结算（经验/金币/掉落/材料/层数）│
│  └─ 现有：装备/技能/锻造/存档 API 全部保留     │
└────────────────────────────────────────────┘
```

要点：实时帧循环只在浏览器跑；Python 不参与逐帧，只在「进入一层」和「清完一层」两个时刻通信。

## 4. 技术准备与资源清单

### 4.1 前端依赖

- Phaser 3（CDN 引入或 npm 装包）
- 可选：构建工具 Vite（若想用 ES module / 热更新）。起步阶段可先用 `<script>` CDN，零构建。

### 4.2 美术资源（最小集，先做 1 个职业）

| 资源 | 内容 | 规格建议 |
|------|------|---------|
| 角色精灵 | 待机 / 行走 / 攻击（4 或 8 方向） | sprite sheet |
| 怪物精灵 | 至少 2~3 种：普通 / 精英 / BOSS，含死亡动画 | sprite sheet |
| 地块 tileset | 地面 / 墙 / 装饰（暗黑地牢风） | 16x16 或 32x32 tile |
| 特效 | 攻击斩击、技能、受击闪白、掉落光柱 | 序列帧 / 粒子 |
| UI | 血球 / 资源球 / 技能图标 / 背包格 | png |
| 音频 | 攻击 / 受击 / 拾取 / BGM | mp3/ogg |

免费资源来源：

- itch.io（搜 "top down dungeon" / "LPC" / "diablo"）
- Kenney.nl（CC0，UI 和 tile 全套）
- OpenGameArt.org
- LPC 角色（4 方向行走攻击，社区素材多）

> 起步阶段：可用纯色方块 / 圆形占位（Phaser `graphics`）跑通玩法，美术后补。

### 4.3 地图方案

- 用 **Tiled** 编辑器画地图，导出 JSON，Phaser 直接加载（含碰撞层）。
- 或：程序化生成简单房间（先固定一张测试图即可）。

## 5. 分阶段实施路线

> 每个 Phase 可独立运行验证。建议按顺序推进，先跑通再补美术。

### Phase 0 — 技术验证（占位图形）
- [ ] 引入 Phaser 3，新建 `web/static/game/` 工程
- [ ] DungeonScene：一个方块代表角色，WASD/鼠标点击移动
- [ ] 一张测试 tilemap + 墙体碰撞
- **验收**：能在地图上走动、撞墙停住

### Phase 1 — 角色接入
- [ ] TitleScene 调现有 `/api/characters` 选/建角色
- [ ] 进场调 `/api/characters/{name}` 拿属性（HP、攻击、资源等）
- [ ] HUD 显示血条 / 资源条 / 等级 / 层数
- **验收**：选角色 → 进入地图 → HUD 正确显示该角色数据

### Phase 2 — 实时战斗核心 ★
- [ ] 新 API `POST /floor/start`：返回本层怪物配置（数量、各怪 hp/atk/def，复用 `generate_monster` 批量生成）
- [ ] 地图生成多只怪物，含 HP 条
- [ ] 敌人 AI：巡逻 → 发现玩家追击 → 近身攻击
- [ ] 玩家攻击：左键近战 / 朝向判定 / 命中扣血（前端实时伤害公式，对齐 `config` 数值量级）
- [ ] 死亡：怪死亡动画 + 移除；玩家死亡 → 返回城镇
- **验收**：能移动、攻击、击杀怪、被怪攻击、清场或阵亡

### Phase 3 — 技能与资源
- [ ] 把 `config/skills.py` 的主动技能映射成「按键技能」（Q/E/R…）
- [ ] CD、资源消耗、技能伤害倍率、buff/治疗/控制效果实时化
- [ ] 技能特效（占位即可）
- **验收**：按键释放技能、消耗资源、走 CD、效果生效

### Phase 4 — 结算与养成闭环
- [ ] 新 API `POST /floor/clear`：传入战果，Python 复用现有逻辑发经验/金币/掉落/锻造材料、推进层数、存档
- [ ] 掉落物在地图上生成光柱，玩家走过拾取 → 入背包
- [ ] 城镇场景 TownScene：背包 / 装备 / 技能 / 锻造 UI（接现有 API）
- **验收**：打完一层 → 拿到奖励 → 回城换装强化 → 再进下一层（完整循环）

### Phase 5 — 表现与打磨
- [ ] 替换占位图为正式美术（角色 / 怪 / tile / 特效）
- [ ] 攻击/受击/拾取/BGM 音效
- [ ] BOSS 层特殊演出、精英怪标识
- [ ] 小地图 / 伤害飘字 / 暴击表现

## 7. 风险与决策点

| 项目 | 说明 | 建议 |
|------|------|------|
| 前后端公式分歧 | 实时战斗在前端算，数值可能与原回合制不一致 | 起步用方案 A，把 config 数值当"量级参考"，单机不校验 |
| 多怪平衡 | 原本 1v1，改多怪同屏后难度需重调 | Phase 2 后单独做一次数值调参 |
| 美术成本 | 8 方向动画素材量大 | 先做 4 方向；或先用占位图跑通玩法 |
| 技能实时化 | 部分技能（buff/控制）原本是回合语义 | Phase 3 逐个重新定义为实时效果 |
| 工程化 | 纯 `<script>` 还是上 Vite | 起步零构建，文件变多后再迁 Vite |
